# 插件商店计划书(GitHub 后端)

> 状态:**计划阶段**,未实现。
> 参考:Obsidian Community Plugins 模式(`obsidianmd/obsidian-releases` 单一索引仓库 + 各插件独立 repo + 提 PR 上架)。

## 1. 目标 / 非目标

**目标**

- 用户能在 Continuo 内浏览、搜索、安装、更新第三方插件,不必复制 git URL
- 索引数据公开 + 版本控制,plugin 作者透明地上架(开 PR)
- 启动时静默检查更新,有更新在 Settings 角标提示
- 官方维护一个"verified"标记(代码 review 过 / 项目方维护)
- 零运营成本(完全跑在 GitHub 上)

**非目标**

- 不做付费插件 / 订阅(超 v0.x 能力)
- 不做插件 sandbox 提升(已知限制见 doc/11 §Phase 4.B 残留)
- 不做插件评分 / 评论(可外链 GitHub Issues 代替)
- 不自建 CDN(GitHub raw 足够;真撞 rate limit 后再说)

## 2. 三方角色

| 角色 | 仓库 | 内容 |
|---|---|---|
| **索引仓库** | `philip1974/continuo-plugins` | `index.json`(全量插件元信息) + `README.md`(上架须知) |
| **插件仓库** | 每个插件一个,如 `philip1974/continuo-sample-plugin` | `manifest.json`(版本源)+ `main.js` + 可选 `styles.css` |
| **Continuo app** | 本仓库 | UI 拉索引、装机器、更新检查 |

数据流:

```
                ┌──────────────────┐
   [用户]  ──→  │ Continuo Settings│  ──fetch──→  index.json (raw.githubusercontent.com)
                │   插件商店 tab    │  ──fetch──→  manifest.json (各 plugin repo)
                └──────────────────┘  ──install→  v4.5 installFromGit
```

## 3. 索引仓库

### 3.1 index.json schema

```json
[
  {
    "id": "com.example.sample",
    "name": "Sample Plugin",
    "description": "演示 9 贡献点 + fs/network demo",
    "author": "philip1974",
    "authorUrl": "https://github.com/philip1974",
    "repo": "philip1974/continuo-sample-plugin",
    "branch": "main",
    "tags": ["sample", "demo", "v5"],
    "verified": true
  }
]
```

- `version` **不写**:版本是 plugin manifest 的源,索引只指方向。app 拉 manifest 取真实版本。
- `tags` 自由字符串数组(Obsidian 也是这样,起步够用,后期再考虑分类枚举)。
- `verified: true` = 官方 review 过(代码读过 + 行为符合预期)。`false` / 缺省 = 社区贡献,自负风险。
- `repo` = `owner/name`,app 拼成 `https://github.com/owner/name.git` 走 v4.5 install。

### 3.2 README.md 上架流程

plugin 作者 fork → 编辑 `index.json` 加一条 → 提 PR。我们 review 代码后合并 + 视情况标 `verified`。

提供 PR 模板(`.github/PULL_REQUEST_TEMPLATE.md`)要求:
- repo URL + manifest 截图
- 简述 plugin 做什么、声明哪些权限
- 自测:在最新 Continuo 上装 + enable + 跑核心命令的截图
- 同意接受 review feedback

## 4. Continuo 端实现

### 4.1 数据层

新文件:`src/marketplace/types.ts`:

```ts
export interface MarketplaceEntry {
  readonly id: string;
  readonly name: string;
  readonly description?: string;
  readonly author: string;
  readonly authorUrl?: string;
  readonly repo: string;        // owner/name
  readonly branch?: string;     // 默认 'main'
```

新文件:`src/marketplace/fetcher.ts`:


实现要点:

- in-memory cache + sessionStorage 持久化(1h TTL)
- error 时 fallback 上次 cache(用户没网也能浏览历史)

### 4.2 Update store

新文件:`src/marketplace/update-store.ts`(zustand):

```ts
interface UpdateState {
  /** id -> latest available version (拉自 plugin manifest) */
  readonly latestVersions: ReadonlyMap<string, string>;
  /** 哪些已装插件有可用更新 */
  readonly available: readonly { id: string; from: string; to: string }[];

  refresh(): Promise<void>;
}
```

启动时调一次 `refresh()` 静默拉,完成后 zustand state 更新驱动 Settings 角标。

### 4.3 UI

**新 SettingTab**(放在现有"插件"之前):

`src/marketplace/MarketplaceTab.tsx`:

- 顶部:搜索框 + tag 筛选 chips
- 列表:每个 entry 一张 card
  - 名称 / verified ✓ 徽章 / 描述 / 作者(链 GitHub)
  - 右侧按钮:`[安装]` / `[已安装]` / `[更新到 vX]`
- 空 / loading / error 三态

按钮状态由 PluginManager.listAll() + update-store.available 推导:
- 未装 → `[安装]` primary,点 → `co.plugins.installFromGit(githubUrl)`(已存在)
- 已装 + 无更新 → `[已安装]` ghost disabled
- 已装 + 有更新 → `[更新到 v0.3]` primary,点 → `uninstall + installFromGit`

**Settings 角标**:`IconSidebar` 的 Settings 齿轮图标右上角加个红圈数字(更新数量),只在 update-store.available.length > 0 时显示。

### 4.4 启动时检查

`src/main.tsx`:

```ts
// 启动后异步拉,不阻塞 UI 渲染
import('./marketplace/update-store').then(({ refreshUpdateStore }) => {
  void refreshUpdateStore().catch((err) =>
    console.warn('[marketplace] update check failed', err),
  );
});
```

## 6. 风险 / 待定

| 风险 | 缓解 |
|---|---|
| GitHub raw 60/hr 不 auth → 多用户撞墙 | 1h cache + sessionStorage 持久化;真撞墙 retry-after 静默退守 |
| index.json 增长大 → 拉慢 | <500 条都不会有体感问题;真到了切 paginated index |
| plugin 作者 PR 灌水 | review 兜底;verified 标记拉开"被审核"和"野生" |
| 旧版本 plugin 不兼容新 Continuo | manifest minLMVersion 已存在(改名后 minContinuoVersion?暂保留 minLMVersion 兼容性) |
| 删除已上架 plugin 的工作流 | PR 删 index.json 行;app 端已装的不动,下次更新拉 manifest 可能 404 → 正常错误处理 |
| update 期间 plugin 数据丢失 | uninstall 会清 _enabled / _permissions(同 v4.6),plugin 自家 `loadData/saveData` 走的是 _data.json **没被清** — 重装后能继续读到 |
| GitHub 索引 repo 被攻陷 | 启用 branch protection + required reviews(我自己 review)|
