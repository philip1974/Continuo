# 20 · 质量编排层方案

> 目标：给 Continuo 补一层**最小够用**的质量编排，让 CI、测试分层、契约门禁、模块冻结串成一条闭环；不照搬 Nous issue #71 的企业级矩阵，只挑高 ROI 的部分落地。

## 一句话定位

**先补 CI 兜底 → 再把 vitest 拆出 integration → 然后把已有 `*-contracts` 类 BDD 收编成 contract 门禁 → 最后给最稳的两三个模块写冻结 checklist。** 不引入新测试框架、不增设 regression 第三档、不串 traceId。

## 背景

Continuo 当前质量资产已不少：

- `src/__tests__/` 下 **123 个 BDD topic**（覆盖 dock / editor / explorer / terminal / plugin-mcp / settings / theme / decor 等）
- `tests/e2e/` 下约 **280 个 Playwright spec**
- `pnpm bdd:index` 已自动生成索引，`/comprehend` 反向 BDD 走同一目录
- `src/design/` 是 Nous shell-ui 的 Continuo 副本，由 `pnpm sync:design:check` 守护

但**质量编排层完全缺失**，缺口比 Nous 还大一档：

| 维度 | Nous issue #71 | Continuo 当前 | 严重度 |
|---|---|---|---|
| CI / PR 门禁 | 已有 | **完全没有** `.github/workflows/` | 🔴 比 Nous 严重 |
| vitest projects 分层 | unit / integration / e2e（部分白名单） | 一锅煮：所有 `*.{spec,test}.{ts,tsx}` 都进默认 `pnpm test` | 🔴 比 Nous 严重 |
| contract 独立门禁 | 缺 | 缺；但 `*-contracts / dock-api-ref / co-api` 已有素材 | 🟡 同 Nous |
| 模块冻结 DoD | 缺 | 缺；`doc/checklist/` 目录不存在 | 🟡 同 Nous |
| Edge case 集中 | 散落 | 散落（`persist-corrupted-* / bom-* / crlf-* / *-rapid-typing`） | 🟡 同 Nous |
| Smoke 分层 | 偏 CLI | 单文件 `tests/e2e/smoke.spec.ts` | 🟢 弱但够用 |

## 不做清单（划红线）

> Continuo 是单 Electron 应用、单人项目，下列项过度设计，**不抄**：

- ❌ **regression 独立第三档**：BDD 都是 UI 行为，与 contract 边界不清，强分会变文档负担
- ❌ **protocol contract test 大体系**：没有 Nous 那种多包跨进程协议
- ❌ **observability traceId 串联**：Electron 单机过度
- ❌ **install / tarball smoke**：还没发布渠道，提前补无意义
- ❌ **新引入测试框架**（如 cypress / wdio）：vitest + Playwright 已够

## 里程碑

---

### M1 · CI 兜底（预计 0.5 天，最高优先级）

**做什么**

- 新增 `.github/workflows/ci.yml`，在 PR / push main 上跑：
  - `pnpm install --frozen-lockfile`
  - `pnpm lint`
  - `pnpm typecheck`
  - `pnpm sync:design:check`（守住 `src/design/` 不漂移）
  - `pnpm test`（vitest）
  - `pnpm e2e`（Playwright，可选独立 job）
- 选一台 macOS runner（Electron 原生模块 + node-pty 易踩坑）
- e2e job 上传 `playwright-report/` 与 `test-results/` 作为 artifact

**done 标准**

- [ ] 任意 PR 自动跑 lint / typecheck / sync:design:check / test 四关，全绿才允许合并
- [ ] e2e job 跑完后能在 GitHub Actions 页面下到 Playwright 报告
- [ ] CI 用的 Node 版本 ≥ `package.json#engines.node` 声明
- [ ] `pnpm-lock.yaml` 不漂移（PR 改动 lockfile 时显式提示）
- [ ] 主分支徽章可挂在 `README` 或 `00-计划书总览.md`（可选）

---

### M2 · vitest projects 分层（预计 0.5 天）

**做什么**

- 把 `vitest.config.ts` 单 config 拆成 vitest projects 形式（unit + integration），保留现有 `environmentMatchGlobs` 行为
- **unit project**：默认 `pnpm test` 命中，包含纯逻辑、stores、hooks、design system jsdom 测试
- **integration project**：包含 `src/integration/**` 与 `src/__tests__/{plugin-mcp-e2e,plugin-mcp-ipc-bridge,plugin-mcp-multi-window,multi-window-workspace,terminal-ipc,terminal-write,terminal-sessions-service}/**`，由 `pnpm test:integration` 单独跑
- 在 `package.json` 新增脚本：
  - `"test:integration": "vitest run --project integration"`
  - `"test:unit": "vitest run --project unit"`
- CI M1 中 `pnpm test` 改为 `pnpm test:unit && pnpm test:integration`，失败信号分开

**done 标准**

- [ ] `pnpm test:unit` 不命中任何 `plugin-mcp-*` / multi-window / terminal-ipc 目录
- [ ] `pnpm test:integration` 只跑上面列出的目录，且本地能跑通
- [ ] 默认 `pnpm test` 行为兼容（运行 unit + integration），不破坏既有用户习惯
- [ ] CI 输出能区分 unit / integration 失败位置
- [ ] BDD 索引（`pnpm bdd:index`）不受影响

---

### M3 · contract 门禁（预计 0.5 天）

**做什么**

- 把以下"契约性"BDD topic 标记为 contract：
  - `co-api`（Continuo 公开 API）
  - `dock-api-ref`（Dockview 集成的 API 参考）
  - `animation-contracts`、`decor-contracts`、`popout-contracts`
  - `agent-terminal-mcp-stdio-framing`（MCP 协议帧）
  - `plugin-mcp-invoke-bridge`、`plugin-mcp-ipc-bridge`（插件 ↔ MCP 协议层）
- 在 vitest projects 加 `contract` project，include 上述目录
- 新增 `"test:contract": "vitest run --project contract"` 脚本
- `scripts/bdd-index.mjs` 输出标记 `[contract]`，方便人工识别

**done 标准**

- [ ] `pnpm test:contract` 只跑上述目录，且通过
- [ ] CI 中 contract 信号独立呈现，contract 失败比 unit 失败优先级更高（reviewer 一眼看出）
- [ ] BDD 索引中 contract topic 有显式标记
- [ ] 新增/删除 contract topic 时，README 或 `co-api/README.md` 同步说明（人工流程，不强制工具）

---

### M4 · 模块冻结 DoD（预计 1 天，挑头两个）

**做什么**

- 新建 `doc/checklist/` 目录
- 写 `doc/checklist/module-freeze-template.md`：列稳定行为契约、BDD topic、必跑命令、回归用例
- 首批冻结候选（**只挑最稳的两个**，其余等真稳了再说）：
  1. `doc/checklist/freeze-design-system.md` — 覆盖 `design-system / design-system-modal / design-system-tabs`，外加 `sync:design:check`
  2. `doc/checklist/freeze-dock.md` — 覆盖 `dock-api-ref / popout-contracts / wrap-panel-close / persist-dock-layout`
- 每份 checklist 顶部声明：**冻结后任何变更必须先在文档加 ADR**

**done 标准**

- [ ] `doc/checklist/` 下有 1 个模板 + 2 个冻结文档
- [ ] 每份冻结文档写清"必跑命令一行"，例如 `pnpm test --project unit src/__tests__/design-system && pnpm sync:design:check`
- [ ] `00-计划书总览.md` 文档索引追加指向 `20-质量编排层方案.md`（**这是确认动作，等到 M4 完成后再做**）
- [ ] 后续 PR 涉及冻结模块时，PR 模板提示 reviewer 跑必跑命令（PR 模板属可选改进）

---

### M5 · 边角补强（预计 0.5 天，可放后续迭代）

**做什么**

- 把零散 edge case BDD（`persist-corrupted-* / bom-file-open / crlf-file-open / *-rapid-typing / workspace-path-with-spaces / unicode-content / special-filename / single-line-long-file`）打 `@edge` 标签或迁移到 `src/__tests__/_edge/`，方便回归矩阵选取
- 把 `tests/e2e/smoke.spec.ts` 拆三档：
  - `smoke-startup.spec.ts`：Electron 主窗口能起、splash 消失
  - `smoke-design.spec.ts`：design system 关键控件可见可点
  - `smoke-mcp.spec.ts`：MCP stdio framing 一次握手
- `package.json` 增 `"test:smoke": "playwright test tests/e2e/smoke-*.spec.ts"`，CI 把它挪到独立短任务

**done 标准**

- [ ] edge case 目录或标签集中后，`grep -r "@edge" src/__tests__` 能枚举
- [ ] `pnpm test:smoke` 整体 < 30s 完成
- [ ] CI smoke job 失败立刻 fail-fast 阻断 e2e 完整跑

## 全流程验收 demo 脚本

打开 PR → CI 自动触发 → 看到 lint / typecheck / sync-design / test:unit / test:integration / test:contract / test:smoke / e2e 八个 check —— 任何一个红，PR 合不进来。本地改 `src/design/` 时 `pnpm sync:design:check` 立刻报错。改了 `dock` 模块时 reviewer 按 `freeze-dock.md` 的必跑命令一键回归。整条质量链不超过 90 秒能解释清楚，能跑就发布。

## 核心约束（不会动摇）

- **极简优先**：只补 CI、分 vitest project、加 contract 门禁、写两份冻结 checklist —— 五件事做完就停，不再扩 regression / observability / smoke 多档
- **不为冻结而冻结**：模块没真稳别写冻结文档，否则一改就废
- **门禁信号要清晰**：unit / integration / contract / smoke / e2e 五档失败要能一眼分辨，不混用
- **不引入新工具**：保持 vitest + Playwright + GitHub Actions 三件套
- **BDD 索引保持唯一真相源**：所有分层只是 vitest project include 的切片，BDD 文件本身不动位置（除 M5 的 `_edge/` 外）

## 风险与回退

| 风险 | 触发条件 | 回退 |
|---|---|---|
| macOS runner 跑 e2e 慢 / 不稳 | Playwright in CI > 10min 或 flake 率 > 5% | 先把 e2e 改为 nightly job，PR 只跑 unit/integration/contract/smoke |
| vitest project 拆分破坏现有 spec | `environmentMatchGlobs` 不能直接套到 project 配置 | 退回单 config，改用 `--testPathPattern` 区分 |
| sync-design 在 CI 偶发漂移 | 路径分隔符 / 行尾差异 | `sync-design.mjs --check` 加 `--ignore-eol` 选项 |
| 冻结文档过早写完没人维护 | 模块还在变 | 直接删除冻结文档，等真稳再写 |
