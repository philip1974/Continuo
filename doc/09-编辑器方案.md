# 09 · Markdown 编辑器方案

> 目标:把 `src/panels/Editor.tsx` 从 9 行的静态占位升级为
> **Milkdown WYSIWYG + CodeMirror 双引擎**编辑器,从 MindAutonAgent 移植。

## 一句话定位

**Milkdown/Crepe 7.20 出 markdown WYSIWYG;CodeMirror 6 出代码 / source 视图;
状态走 LayoutMotion 的 Zustand;接 Explorer 已有 fs.* IPC,无新通道。**

## 借鉴出处

| 来自 | 借鉴什么 |
|---|---|
| `~/Desktop/MindAutonAgent-Electron/src/renderer/features/editor/` | 整套编辑器架构(Milkdown+CodeMirror 双引擎、3 mode、tab 系统、auto save) |
| Mind 的 Crepe 配置 | features 启用清单(CodeMirror/Table/Toolbar/Placeholder/...,关 Latex/ImageBlock) |

## 关键决策

| # | 决策 | 选择 | 不选的代价 |
|---|---|---|---|
| 1 | Tab 系统 | **Editor panel 内自管 tab**(VSCode 风) | Dockview 多 panel 太散,与"打开文件"语义不符 |
| 2 | Crepe 主题 | `frame-dark.css` 直接用 | 不折腾自定义 CSS |
| 3 | 自动保存 | **Markdown 2s 防抖自动保存,代码必须 Cmd+S** | 笔记不丢,代码避免误存 |
| 4 | Source mode | **CodeMirror markdown 模式**(语法高亮 + 折叠) | 比 Mind 的纯 textarea 强 |
| 5 | 状态库 | Zustand vanilla(沿用 ADR-007) | Jotai 重写为 Zustand |
| 6 | 不做的功能 | KaTeX / Mermaid / 图片拖入 / 找替换 | MVP 留下里程碑 |

## 接口契约

### 共享 Editor Tab 模型(从 Mind 移植)
```ts
export interface EditorTab {
  id: string;              // filePath || `untitled-${uuid}`
  filePath: string | null; // null = 未保存草稿
  content: string;
  originalContent: string; // 用于 dirty 比对
  dirty: boolean;
}
```

### Zustand Store API
```ts
type EditorState = {
  tabs: EditorTab[];
  activeTabId: string | null;
  mode: 'edit' | 'source' | 'preview';

  // 派生(不存,UI 用 selector 取)
  // activeTab = tabs.find(t => t.id === activeTabId)

  openTab: (tab: EditorTab) => void;          // 已存在则切换,新加则推入
  closeTab: (id: string) => void;             // 关闭 + 自动选下一个
  switchTab: (id: string) => void;
  updateContent: (id: string, content: string) => void;  // 编辑器 onChange
  markSaved: (id: string, savedContent: string) => void; // 保存成功后
  setFilePath: (id: string, newPath: string) => void;    // 另存为后改 id+path
  setMode: (mode: EditorMode) => void;
};
```

不引 Jotai。沿用 closing.store / explorer.store 的 zustand `create()` 模式。

### IPC 通道
**0 个新通道**。完全复用:
- `window.api.fs.readFile(path)` — 打开文件
- `window.api.fs.writeFile(path, content)` — 保存(走 atomic write,Step 1 已实现)
- `window.api.fs.selectDirectory()` — 选 workspace(已用过)
- `window.api.fs.onDirChanged(...)` — 外部修改 → 提示重读(M-Editor MVP 暂不接,下里程碑)

## 与 Explorer 的接入(Step E5)

Explorer FileRow **单击** → 触发 Editor 打开。两种实现方式:
- **(a)** Explorer 直接调 `useEditorStore.getState().openTab(...)` —— 跨 panel 直接耦合 store
- **(b)** 走 EventBus(自定义事件) —— 解耦,但多余抽象

选 **(a)**,理由:Zustand store 本来就是全工程共享的"全局总线",没必要再加抽象层。Explorer 的 onClick 调 `openFile(path)` helper,helper 内部:
```ts
async function openFile(path: string) {
  const r = await window.api.fs.readFile(path);
  if (!r.ok) return alert(`打开失败:${r.message}`);
  useEditorStore.getState().openTab({
    id: path, filePath: path,
    content: r.data, originalContent: r.data, dirty: false,
  });
}
```
