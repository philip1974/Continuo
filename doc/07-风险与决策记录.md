# 07 · 风险与决策记录

## 已知风险

### R1 · Dockview 自带 popout 与 Electron BrowserWindow 冲突

**现象**：Dockview 的 popout 用 `window.open`，Electron 默认会打开新 BrowserWindow，但配置（preload、安全策略、尺寸）由 Chromium 默认值决定，我们拿不到控制权。

**影响**：popout 窗口里 `window.api` 是 `undefined`，无法读 layout，无法 IPC。

**缓解**：
- v1：保留 Dockview 自带 popout（仅主屏可用），通过 `app.on('web-contents-created')` 在 main 进程拦截新建的 webContents，强制把 preload 注进去。
- v2：完全接管，监听 Dockview 的 group location change，自己起 BrowserWindow（详见 `05-Electron-集成.md`）。

---

### R2 · `layoutId` 与 Dockview 内部 portal 冲突

**现象**：Dockview 内部用 React Portal 把 panel body 渲染到某个虚拟 DOM 节点，Motion 的 `layoutId` 跨 portal 时可能测不到正确尺寸。

**影响**：跨 group 的 `panel-title-${id}` shared layout 动画可能"飞"到错的位置。

**缓解**：
- 落点 ③ 在 v1 标记为"可选"，先做 ① ② 两个稳的。
- 真做时用 Motion 的 `layoutScroll` + `layoutDependency` 控制测量时机。
- 出问题就降级为 `AnimatePresence` 单纯淡入淡出。

---

### R3 · 装饰层 SVG 在长时间运行下 GPU 占用上升

**现象**：Background Beams 的 SVG 持续动画在 macOS Activity Monitor 里能看到 GPU 5%~10% 持续占用。

**影响**：电池续航下降；用户长时间挂着会发热。

**缓解**：
- Beams 只在 EmptyState 出现，dock 有 panel 时 unmount。
- 监听 `document.visibilityState === 'hidden'` → 暂停 SVG 动画。
- prefers-reduced-motion / 低电量模式下退化为静态渐变。

---

### R4 · React 19 与 Motion 的并发渲染兼容性

**现象**：Motion 的 layout 测量阶段在 React 19 自动 batching 下偶发 1 帧错位（社区已有 issue）。

**影响**：tab 切换瞬间 indicator 可能跳一下。

**缓解**：
- 锁 motion 到当前最新稳定版（cargo 锁版本）。
- M3 验收必须在 React 19 + Motion 当前版下手动验"切 100 次 tab 0 跳变"。
- 出 issue 时降到 React 18.3 是兜底方案（不到万不得已不动）。

---

### R5 · layout.json schema 演进

**现象**：未来加新 panel / 改 group 类型 → 老的 `layout.json` 反序列化失败。

**影响**：用户重启后布局丢失，体验差。

**缓解**：
- JSON 顶层带 `version`，写 migration 函数。
- 解析失败永远落回 `defaultLayout`，不抛异常。
- 升级时把旧 `layout.json` 备份成 `layout.v1.json` 留作 debug。

---

## ADR 记录

### ADR-001 · 选 Dockview 而不是 Allotment

- **背景**：两者都派生自 VSCode 源码。
- **决策**：选 Dockview。
- **理由**：Dockview 内建 popout API + tab dock，Allotment 只做分栏。我们规划里"拖出独立窗口"是核心卖点，Allotment 实现成本远高于 Dockview。
- **不选的代价**：Dockview 的 API 比 Allotment 复杂，学习曲线略陡。

### ADR-002 · 装饰组件复制源码而非装包

- **背景**：Aceternity / Magic UI 都提供 npm 包。
- **决策**：复制源码。
- **理由**：(1) 官方文档就是 copy-paste 工作流；(2) 复制后能删冗余 props 减体积；(3) 不被外部包版本绑定。
- **不选的代价**：未来升级 Aceternity 时要手动 diff，但反正只用 2 个组件。

### ADR-003 · 不引入 tRPC / electron-store

- **背景**：Electron IPC 通道才 3 个，state store 也只是 layout.json。
- **决策**：手写 zod-validated ipcMain.handle + fs/promises。
- **理由**：复杂度远小于上 tRPC / electron-store 的边际收益。
- **不选的代价**：通道增多到 ~10 个时再考虑迁移。

### ADR-004 · Tab indicator 用 spring，PanelMount 用 ease-out tween

- **背景**：两者节奏感不同，spring 更"弹"，tween 更"滑"。
- **决策**：indicator = spring（stiffness 500 / damping 35），PanelMount = tween 220ms ease。
- **理由**：indicator 是高频小元素，spring 的快速到位 + 微震尾感觉灵敏；PanelMount 是大块进出场，spring 会显得轻浮，tween 更稳。
- **不选的代价**：两套 transition 配置需要在代码里维护两份。

## 待回答问题（提给业主 / 自己）

1. **是否需要 Windows 标题栏定制？** 影响 BrowserWindow `frame` / `titleBarStyle` 选项。
2. **popout 窗口关闭时，panel 是回到原 group 还是丢弃？** 影响 v2 的 IPC 协议设计。
3. **layout.json 是否需要云同步？** 如果要，需要切到带认证的存储而不是纯 fs。
4. **是否计划支持插件化（第三方注册 panel）？** 这会影响 panel registry 的 API 表面。
