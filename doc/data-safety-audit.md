42. **`explorer:read` 失败后仍注册持久化写订阅 → 后续 store 变化把真实数据覆盖为默认态**(`lib/persist/explorer-persist.ts`,codex P1,「读失败→写覆盖」族在 init 层)— `initExplorerPersistence` 的 `api.read()` 返回 `{ok:false}`(EACCES/EIO 经 safeHandle)或 reject 时:既不 hydrate 旧 explorer.json,又仍 `markHydrated` + 注册 `writeNow`/debounce 写订阅。store 停在**默认/未恢复态**,后续任意 root/tab/expanded 变化 → `snapshotFromStores`(基于默认 store)→ `api.write` → main `explorer:write` 重读 merge 后把真实 `recentRoots`/`pinned`/`window`/`editor` 段覆盖为空/默认。→ 引入 `loadTrusted`(= `read` 的 `r.ok`:首启 null / 合法 snapshot / 损坏都算「成功读到磁盘当前态」=可信;`!ok`/reject=不可信);**仅可信时注册写订阅/flush**,不可信则 `markHydrated` 后早返回(不订阅、不写,磁盘不动,留待重启重读恢复)。+TDD(read ok=false / read reject → 后续 store 变化均不调用 `api.write`)。

## DEFER:rename-swap 崩溃窗口族(需统一事务原语)
- **plugin-fs atomicReplaceWithinScope**(`plugin-fs.service.ts:616`)— `rename(final→.trash-*)` 与 `rename(staging→final)` 间崩溃 → 原文件只剩隐藏 trash + final 缺失;且 `sweepStaleTrashInDir` 会在 TTL(24h)后**删除** trash → **永久丢失**。
- 与上面 #3(plugins.service overwrite)**同族**。
- **为何 DEFER**:naive「final 缺失就还原 trash」有假阳性——replace 已完成、trash 泄漏未删、用户随后删 final 时,还原会**复活用户已删的文件**(数据/隐私问题)。安全解需**可恢复事务标记**(swap 前写 marker,完成/回滚后删;启动按 marker 明确完成或回滚),区分「崩溃中途」vs「已完成泄漏」。建议抽一个共享 transactional-replace 原语,同时覆盖 plugins.service 与 plugin-fs。
- 临时缓解(可选,安全但不完整):`sweepStaleTrashInDir` 对 final 缺失的 trash **不按 TTL 删除**(至少不永久丢,留待手动/事务恢复)。
