# Continuo · Electron Shell + 多窗格 IDE 计划书

> 目标：用最少依赖搭一个 **VSCode 级别可拖动多窗格 + 共享元素动画 + 1~2 个炫酷装饰** 的 Electron 桌面壳。

## 一句话定位

**Electron 做宿主，Dockview 做骨架，Motion `layoutId` 做过渡，Aceternity / Magic UI 抄 1~2 个装饰组件点缀启动页和空状态。** 不堆功能、不堆装饰，所有"炫酷"只服务于"用户能感知到面板间关系"。

## 技术选型表

| 层级 | 选型 | 替代方案 | 不选替代的原因 |
|---|---|---|---|
| 桌面壳 | Electron 30+ | Tauri | 需要 popout 多窗口 + 成熟的 BrowserWindow API |
| 渲染框架 | React 19 | Vue / Solid | Dockview / Motion / Aceternity 全在 React 生态最成熟 |
| 构建 | Vite + electron-vite | webpack | HMR 快，配置少 |
| 多窗格骨架 | **Dockview** | Allotment / FlexLayout / rc-dock | 唯一同时支持 dock + tab + popout 到独立 BrowserWindow，且零运行时依赖 |
| 动画引擎 | **Motion (motion/react)** | GSAP / React Spring | `layout` / `layoutId` / `AnimatePresence` 是 shared element 切换的事实标准 |
| 装饰组件 | **Aceternity UI + Magic UI**（按需复制） | 整个抄过来 | 只挑 Spotlight + Background Beams + Bento Card 三个，避免视觉过载 |
| 样式 | Tailwind v4 | CSS Modules | Aceternity / Magic UI 默认 Tailwind |
| 状态 | Zustand | Redux / Jotai | Dockview 自己持有 layout 状态，业务态量级小；vanilla 化与 Nous CLI 同款,便于将来联动 |
| IPC | Electron contextBridge + zod | tRPC-electron | 三五个通道不值得上 tRPC |
| 资源管理器树 | **headless-tree** + `@tanstack/react-virtual` | react-arborist / rc-tree | 异步 IPC 适配优雅、与 Motion 0 摩擦、Bundle 小，详见 `08-资源管理器方案.md` |
| 文件图标 | `@react-symbols/icons` | 自维护 SVG 集 | 200+ 文件类型自动映射，零维护 |
| Markdown 编辑器 | **Milkdown/Crepe 7** + `@milkdown/react` | MDXEditor / Tiptap / react-markdown | WYSIWYG 体验最接近 Notion；Crepe 一键启用 toolbar+表格+代码块；详见 `09-编辑器方案.md` |
| 代码 / source 编辑器 | **CodeMirror 6** | Monaco / Ace | bundle 小 10×、启动快、移动端友好 |

## 核心约束（不会动摇）

- **极简优先**：能不引入新依赖就不引入。装饰组件复制源码进来，不安装包。
- **协议优先**：Electron main / preload / renderer 之间只走声明过的 IPC 通道，preload 用 `contextBridge` 白名单导出。
- **Dock 状态唯一真相源**：layout 序列化由 Dockview 自带 API 输出，存到 `userData/layout.json`，不自己造轮子。
- **动画从不阻塞布局**：所有 `layoutId` 仅作用于"已经被 Dockview 安排好位置的 DOM"，Motion 只负责帧间补间。
- **装饰可降级**：Spotlight / Beams 在低性能设备（GPU info 探测或用户偏好 prefers-reduced-motion）自动关闭。
