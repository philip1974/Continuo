# 08 · 资源管理器方案

> 目标:把 `src/panels/Explorer.tsx` 从 9 行的静态占位,升级成 **VSCode 风的可用文件资源管理器**。极简,可联动,为将来嵌 Nous Agent 做铺垫。

## 一句话定位

**`headless-tree` 出渲染骨架,`Nous` 风 IPC 出主进程文件 API,`file-tree-alternative` 出 UX(搜索/排序/Pin/右键菜单),Zustand 出状态层,VSCode 风 workspace 出权限语义。**

## 三方借鉴出处

| 来自 | 借鉴什么 | 备注 |
|---|---|---|
| `examples/headless-tree` | 树渲染逻辑(useTree + features 插件) | 替代 react-arborist,virtualization 外接 `@tanstack/react-virtual` |
| `examples/file-tree-alternative` | UX 设计(搜索框/Pin 置顶/多维排序/Zoom focus/Dropzone) | Obsidian 强耦合的 vault/menu/setting 部分丢弃 |
| `~/Desktop/Nous` | IPC 通道命名(`fs:list-dir`/`fs:watch-dir`)+ `safePath` 风格 + 类型化 channel-map | 不做 home 沙箱(VSCode 风) |
| `~/Desktop/MindAutonAgent-Electron` | `IpcResult<T>` 结构化错误 + watcher 资源管理思路 | 简化版采纳 |

## 关键决策(对应前期讨论)

| # | 决策 | 选择 | 不选的代价 |
|---|---|---|---|
| 1 | 树渲染引擎 | **headless-tree**(逻辑库)+ `@tanstack/react-virtual` | 自管虚拟滚动 ~10 行胶水;换来与 motion/Tailwind 0 摩擦、Bundle 小 25KB+ |
| 2 | 状态库 | **Zustand**(沿用 5.0.2,与 Nous CLI 对齐) | 联动 Nous 时 store 同款;对当前规模够用 |
| 3 | 节点展开动画 | **暂不接 motion** | 先稳定 MVP,后续可在 `<AnimatePresence>` 里包 row |
| 4 | 路径权限模型 | **VSCode 风:无 IPC 沙箱 + workspace root + UX 确认** | 信任 OS 权限;删除/重命名走前端确认弹窗 |

## 进程模型与数据流

```
┌──────────────────────────────────────────────────────────────┐
│  Main (Node)                                                 │
│    fs.ipc.ts                                                 │
│      所有 handler 通过 safeHandle(channel, schema, fn) 注册:  │
│        ① 校验 event.senderFrame origin (防越权)              │
│        ② zod.parse 入参                                       │
│        ③ 调用业务 fn → 包成 IpcResult<T> 返回                  │
│      通道:fs:list-dir / fs:read / fs:write / fs:rename       │
│            fs:remove / fs:create / fs:watch / fs:unwatch     │
│            fs:dialog / fs:reveal / fs:open                   │
│    fs.watch(recursive:true) → webContents.send('fs:changed') │
└────────────────────────┬─────────────────────────────────────┘
                         │ contextBridge 白名单
┌────────────────────────▼─────────────────────────────────────┐
│  Preload                                                     │
│    window.api.fs = { listDir, readFile, ..., onChange }      │
│    用 zod schema 校验入参,出参原样转发                         │
└────────────────────────┬─────────────────────────────────────┘
                         │
┌────────────────────────▼─────────────────────────────────────┐
│  Renderer · Explorer panel                                   │
│    Zustand stores                                            │
│      explorer.store.ts   → workspaceRoot / sort / search     │
│      pinned.store.ts     → 持久化(electron-store,留待接)     │
│    headless-tree useTree                                     │
│      dataLoader.getChildren(path) = window.api.fs.listDir()  │
│    @tanstack/react-virtual 虚拟滚动                           │
│    onChange(path) → tree.getItemInstance(path).invalidate()  │
└──────────────────────────────────────────────────────────────┘
```

**关键单向流**:用户操作 → Zustand action / tree API → IPC → 主进程 fs → IpcResult → 更新 store / 刷新树。
**外部驱动流**:fs.watch → IPC 事件 → renderer 调 `invalidateChildrenIds()` 增量刷新单节点,**不重建全树**。

## 接口契约(主/渲染共享)

> **`IpcResult<T>` 是全工程共用 envelope**(已落地在 `electron/shared/ipc-result.ts`)。既有的 `layout:read` / `layout:write` / `popout:open` 已迁移到此结构,fs.* 新通道沿用同模式(详见 ADR-010)。语义是"IPC envelope"而非 fs 专属,放 `electron/shared/` 是因为 IpcResult 由主进程 safeHandle 生产、preload 与 renderer 消费,electron 是更底层的所有者(`src/lib/api.d.ts` 引 `electron/preload` 是同向依赖)。

```ts
// electron/shared/ipc-result.ts (已存在)
export type IpcResult<T> =
  | { readonly ok: true; readonly data: T }
  | { readonly ok: false; readonly code: string; readonly message: string };

export const IPC_ERR = {
  DENIED: 'IPC_DENIED',         // safeHandle senderFrame 校验失败
  BAD_INPUT: 'IPC_BAD_INPUT',   // zod 校验失败
  HANDLER_ERROR: 'IPC_HANDLER_ERROR', // handler 抛错且未带 code
} as const;

// 业务通道自定义 code 字符串(safeHandle 透传):
//   'FS_NOT_FOUND' | 'FS_DENIED' | 'FS_IO' | 'POPOUT_NOT_IMPLEMENTED' | ...

export interface FileEntry {
  path: string;        // 绝对路径,作为 headless-tree 的 id
  name: string;        // basename
  isDirectory: boolean;
  isSymlink?: boolean;
  size?: number;
  mtime?: number;
  ctime?: number;
}

export interface ListDirOptions {
  maxDepth?: number;        // 默认 1(仅当前层),传 >1 才递归
  exclude?: readonly string[]; // basename 黑名单,默认见下
  followSymlinks?: boolean; // 默认 false
}

export interface FsApi {
  listDir(path: string, opts?: ListDirOptions): Promise<IpcResult<FileEntry[]>>;
  readFile(path: string): Promise<IpcResult<string>>;
  writeFile(path: string, content: string): Promise<IpcResult<void>>;  // 原子写,见下
  rename(oldPath: string, newName: string): Promise<IpcResult<string>>; // 返回新 path
  remove(path: string, opts?: { trash?: boolean }): Promise<IpcResult<void>>;
  createFile(dir: string, name: string): Promise<IpcResult<string>>;
  createDir(parent: string, name: string): Promise<IpcResult<string>>;

  watchDir(path: string): Promise<IpcResult<void>>;
  unwatchDir(path: string): Promise<IpcResult<void>>;
  onChange(cb: (e: { path: string; type: 'rename' | 'change' }) => void): () => void;

  selectDirectory(): Promise<string | null>;     // 弹原生 dialog
  reveal(path: string): Promise<void>;            // shell.showItemInFolder
  open(path: string): Promise<void>;              // shell.openPath
}
```

**`listDir` 防御性约束**(借鉴 Lokus `read_directory_contents_with_depth`):

```ts
const DEFAULT_MAX_DEPTH = 10;     // 硬上限,防 symlink 死循环
const DEFAULT_EXCLUDE = [
  '.git', '.svn', '.hg',
  'node_modules', '.DS_Store', 'Thumbs.db',
] as const;
```

- handler 内强制 `Math.min(opts.maxDepth ?? 1, DEFAULT_MAX_DEPTH)`,调用方传再大也截断
- `exclude` 默认应用,调用方可传空数组覆盖(显式表达"我要看 .git")
- 检测到 symlink 时:`followSymlinks=false` 走 `lstat` 不递归;`true` 走 `stat` 但仍受 `maxDepth` 兜底

**`writeFile` 原子写要求**(借鉴 Lokus `atomic_write_file`):

```
1. 写入 ${path}.tmp
2. fsync(fd) 强制落盘
3. 若 ${path} 存在,先 rename 到 ${path}.backup
4. rename ${path}.tmp → ${path}   ← 原子操作,崩溃也不丢
5. 删 ${path}.backup
```

- 任何步骤失败 → 回滚 backup,IpcResult 返回 `{ ok: false, code: 'FS_IO' }`
- 不引入新依赖,纯 `fs.promises` 实现
- 编辑器场景(M-Editor 里程碑)直接受益,**MVP 资源管理器的 createFile 也走这条路径**

**沙箱规则(VSCode 风,只做基础规范化)**:

```ts
// electron/main/ipc/path-utils.ts
export function normalizePath(input: string): string {
  const abs = path.resolve(input);  // 解析 ../,统一分隔符
  // 不做 home 边界检查
  // 不做敏感目录黑名单
  // 失败由 fs API 自然抛错(EACCES/ENOENT),IpcResult 包装返回
  return abs;
}
```

## Zustand store 设计

```ts
// src/stores/workspace.store.ts
type WorkspaceState = {
  root: string | null;                  // 单 root MVP,Multi-root 留扩展
  recentRoots: string[];                // 最多 5 个,LRU
  setRoot: (path: string) => void;      // 同时写 electron-store
};

// src/stores/explorer.store.ts
type ExplorerState = {
  activePath: string | null;            // 焦点(箭头键导航锚点 + 单击单选)
  selectedPaths: ReadonlySet<string>;   // 多选集合(批量操作目标)
  lastAnchorPath: string | null;        // Shift 范围选的另一端
  expandedPaths: ReadonlySet<string>;   // 展开的目录(持久化)
  sort: { by: 'name' | 'mtime' | 'ctime' | 'size'; reverse: boolean };
  search: string;                       // typeahead 模糊匹配
  toggleExpand: (path: string) => void;
  selectSingle: (path: string) => void;       // 普通 click
  selectToggle: (path: string) => void;       // Cmd/Ctrl+click
  selectRange: (path: string, flat: string[]) => void; // Shift+click
  setSort: (s: ExplorerState['sort']) => void;
};

// src/stores/pinned.store.ts
type PinnedState = {
  paths: string[];                      // 顺序保留,Pin 在文件列表置顶
  toggle: (path: string) => void;
};
```

**vanilla 化**:三个 store 内部都用 `createStore` from `zustand/vanilla` + `useSyncExternalStore` 消费,理由是为将来给 Nous 主进程 bridge 共享(参考 Nous CLI 的 `agent-loop-ui-store.ts`)。

## headless-tree 配置(`tree-config.ts`)

```ts
import {
  asyncDataLoaderFeature, selectionFeature, hotkeysCoreFeature,
  searchFeature, renamingFeature,
} from '@headless-tree/core';

export function createTreeConfig(root: string) {
  return {
    rootItemId: root,
    getItemName: (item) => item.getItemData().name,
    isItemFolder: (item) => item.getItemData().isDirectory,
    indent: 16,

    dataLoader: {
      getItem: async (path: string) => {
        const r = await window.api.fs.listDir(path);  // 父目录拿 entry
        // 实际细节由 hooks 层封装,见 useFileTree.ts
      },
      getChildren: async (path: string) => {
        const r = await window.api.fs.listDir(path);
        return r.ok ? r.data.map(e => e.path) : [];
      },
    },

    features: [
      asyncDataLoaderFeature,
      selectionFeature,
      hotkeysCoreFeature,
      searchFeature,
      renamingFeature,
      // dragAndDropFeature,  // M3 再加
    ],
  };
}
```

**为什么不接 `dragAndDropFeature` 进 MVP**:文件移动(跨目录拖拽)需要 IPC 增 `fs:move`,且 UX 上要做"复制 vs 剪切 vs 移动"的判断,留到后续里程碑。

## VSCode 风 workspace 行为约定

| 场景 | 表现 |
|---|---|
| 启动且无历史 root | Explorer 渲染 `<EmptyWorkspace />`,中央按钮"打开文件夹" |
| 启动且有历史 root | 自动恢复上次的 root,展开状态从 `expandedPaths` 还原 |
| 用户点"打开文件夹" | 调 `fs.selectDirectory()` → 写 `workspaceRoot` → 刷新树 |
| root 路径不再存在 | 树退化到 `<EmptyWorkspace />`,提示"目录已被移除" |
| 删除文件 | 弹 React 确认对话框 → `fs.remove(path, { trash: true })`(默认走系统回收站) |
| 重命名 | headless-tree `renamingFeature` 行内编辑 → `fs.rename` |
| 多 root | **MVP 不做**,store 字段 `root: string \| null` 已留单/多兼容 |

### 多选交互(借鉴 Lokus FileTreeView)

判定优先级 **Shift > Cmd/Ctrl > 普通 click**:

| 操作 | 行为 | 调用 |
|---|---|---|
| 普通 click | 清空选择 → 选当前 → activePath = 当前 → lastAnchor = 当前 | `selectSingle(path)` |
| Cmd/Ctrl+click | 切换当前在选择集中的存在性 → activePath = 当前 → lastAnchor = 当前 | `selectToggle(path)` |
| Shift+click | 以 lastAnchor 到当前 path 在 `flat`(当前可见扁平列表)中的范围替换选择集 → activePath = 当前(lastAnchor 不动) | `selectRange(path, flat)` |
| 箭头键导航 | 移动 activePath,**不**改 selectedPaths(VSCode 行为) | headless-tree hotkey |
| Esc | 清空 selectedPaths(保留 activePath) | UI 层调 store |

批量操作(右键删除 / 拖拽移动)目标 = `selectedPaths`,若为空则退化为 `activePath`。
