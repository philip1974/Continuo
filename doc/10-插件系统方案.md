# 10 · 插件系统方案

> 仿 Obsidian 的"贡献式 + disposable"轻量插件系统,**不仿 VSCode**(extension host 太重)、**不仿 Zed**(WASM 与 LM 的 React+Dockview 强耦合冲突)、**不抄 Lokus**(过度沙箱化,VSCode-fan-out 反例,详见 §12)。

## 一句话定位

**Plugin 是一个继承 `Plugin` 抽象类的 TS 模块,在 `onload()` 里通过 `this.register*` 注册贡献到 Dockview / 命令面板 / 状态栏 / Explorer 等扩展点;`onunload()` 自动清理,因为所有 register 的资源走 disposable 模型。**

## 不做(明确划线)

- ❌ 独立进程 / Web Worker 沙箱(VSCode、Lokus 都这么做,但跟 React+Dockview+Zustand 强耦合冲突,得引入异步 RPC,复杂度爆炸)
- ❌ Manifest `contributes` 大对象静态声明(VSCode 模型,只在沙箱里有意义;无沙箱场景下运行时 `register*` 更直接)
- ❌ Permission 声明(50+ enum 是 Lokus 的反面教材,LM 单用户 + AI agent 信任度高)
- ❌ Plugin marketplace v1(主用户路径是"AI 帮我装/写插件",不是逛商店)
- ❌ 跨平台抽象(Plugin 直接拿 React + Zustand store 用,这是 LM 的优势,不要抹掉)

## 选型对比

| 维度 | Obsidian | Zed | Lokus(反例) | LM 选择 |
|---|---|---|---|---|
| 语言 | TS/JS | Rust → WASM | TS/JS | **TS(ESM,LM 用 Vite)** |
| 隔离 | 无 | WASM 沙箱 | Web Worker + 50+ permission enum | **无** |
| 贡献点粒度 | imperative `register*` | declarative TOML + trait | declarative `contributes` 50+ 字段 | **imperative** |
| 热更新 | disable/enable 走 disposable | 重启 / reload extension | 同 Obsidian | **disable/enable** |
| 学习曲线 | 低(写 class) | 高(Rust + WIT) | 高(VSCode-fan-out) | **低** |

**核心借鉴 Obsidian**,理由:LM 已是 TS+React+Zustand,class-based + disposable 模型最自然;无沙箱单进程让 plugin 直接吃 Dockview API、Zustand store、design 组件,零 RPC 摩擦。

## 架构

### Plugin 父类(disposable 模型)

```ts
// src/plugins/Plugin.ts
export abstract class Plugin {
  readonly app: LMApp;          // 暴露 stores / api / dock 等
  readonly manifest: PluginManifest;
  private disposables: Disposable[] = [];

  constructor(app: LMApp, manifest: PluginManifest) { ... }

  abstract onload(): void | Promise<void>;
  onunload?(): void | Promise<void>;

  /** 内部:每个 register* 都把返回值 push 进来,unload 时统一 dispose */
  protected register(d: Disposable): void {
    this.disposables.push(d);
  }

  // ── 8 个核心贡献点 ─────────────────────────────────
  registerPanel(spec: PanelSpec): Disposable {
    const d = lmDock.addPanelType(spec);
    this.register(d);
    return d;
  }
  addCommand(cmd: CommandSpec): Disposable { ... }
  addStatusBarItem(spec: StatusItemSpec): Disposable { ... }
  addRibbonAction(icon: ReactNode, title: string, fn: () => void): Disposable { ... }
  registerEvent(ref: EventRef): Disposable { ... }
  addSettingTab(tab: SettingTab): Disposable { ... }
  loadData<T>(): Promise<T | null> { ... }
  saveData(data: unknown): Promise<void> { ... }

  /** 内部生命周期管理(LM 内核调用) */
  async _activate(): Promise<void> {
    await this.onload();
  }
  async _deactivate(): Promise<void> {
    for (const d of this.disposables.reverse()) d.dispose();
    this.disposables = [];
    await this.onunload?.();
  }
}

interface Disposable { dispose(): void }
```

**关键:disposable 模型是这套 API 的脊柱**。所有贡献点都返回 `Disposable`,plugin 父类自动收集,`unload` 时 LIFO dispose。这一条解决了 plugin 重载的内存/句柄泄漏。

### 8 个核心贡献点(LM 现有面板系统量身定做)

| API | 等价 Obsidian | LM 内部实现 |
|---|---|---|
| `registerPanel({ type, factory, title })` | `registerView` | Dockview `panelComponents[type] = factory` |
| `addCommand({ id, name, hotkey, fn })` | `addCommand` | 命令面板 store + keybinding registry |
| `addStatusBarItem({ side, component })` | `addStatusBarItem` | StatusBar 注入点(扩展自 LM 现有 footer) |
| `addRibbonAction(icon, title, fn)` | `addRibbonIcon` | IconSidebar 第二组(active bar 区) |
| `registerEvent(ref)` | `registerEvent` | LM EventBus(panel-opened / file-saved 等) |
| `addSettingTab(tab)` | `addSettingTab` | Settings Modal 内一个 SegmentedControl 项 |
| `loadData<T>() / saveData(o)` | 同名 | `userData/plugins/<id>/data.json` 原子写 |
| `registerProtocolHandler('lm://...')` | 同名 | Electron `app.setAsDefaultProtocolClient` |

可选(M-Plugin v2):`registerExplorerDecorator` / `registerEditorAction` / `registerEditorExtension`(注入 CodeMirror 6 扩展)。

### LMApp 暴露面

```ts
interface LMApp {
  readonly version: string;         // LM 应用版本(用于 minLMVersion 检查)
  readonly stores: {
    workspace: typeof useWorkspaceStore;
    editor: typeof useEditorStore;
    terminal: typeof useTerminalStore;
    layoutUi: typeof useLayoutUiStore;
  };
  readonly dock: LMDockApi;         // 包装 Dockview 的稳定 API
  readonly events: LMEventBus;      // panel-opened / file-saved / theme-changed 等
  readonly fs: typeof window.api.fs; // 受信文件系统(后期可加 capability)
  readonly log: PluginLogger;       // 自动加 plugin id 前缀
}
```

**注意**:不直接暴露 `window.api`(IPC 全集),只挑稳定子集。Plugin 想 IPC 之外的能力 → 提 issue / 走核心扩展。

## 插件目录约定

```
{userData}/LayoutMotion/plugins/<plugin-id>/
  manifest.json     必填
  main.js           必填,ESM bundle(import.meta 可用)
  styles.css        可选,自动注入到 head
  data.json         loadData/saveData 持久化
  README.md         可选,Settings UI 显示
```

`{userData}` 来自 Electron `app.getPath('userData')`,macOS 是 `~/Library/Application Support/LayoutMotion/`。

### manifest.json

```json
{
  "id": "com.example.markdown-toc",
  "name": "Markdown TOC",
  "version": "0.1.0",
  "main": "main.js",
  "description": "在编辑器侧边显示 markdown 大纲",
  "author": "Foo Bar",
  "authorUrl": "https://github.com/foo",
  "minLMVersion": "0.2.0",
  "isDesktopOnly": true
}
```

字段直接抄 Obsidian 9 个,不加 `contributes` / `activationEvents` / `permissions`。`main` 默认 `main.js`,允许覆盖(但必须 ESM 单文件)。

### 与 Obsidian 的差异

| 项 | Obsidian | LM |
|---|---|---|
| Bundle 格式 | CommonJS(esbuild --format=cjs) | **ESM**(LM 用 Vite,与现代生态一致) |
| 入口加载 | `require(path)` | `import(filePath)` |
| 主类导出 | `module.exports = MyPlugin` | `export default class extends Plugin` |
| 样式注入 | `styles.css` 自动加 `<style>` 标签 | 同 |

## 加载与生命周期

```
LM 启动
  └─ PluginManager 扫 ${userData}/plugins/*/manifest.json
       ├─ 解析 manifest(zod 校验,失败跳过)
       ├─ 检查 minLMVersion 兼容
       ├─ 启用列表(${userData}/plugins/enabled.json)过滤
       └─ 对每个启用插件:
           ├─ dynamic import(`${dir}/main.js`)
           ├─ new PluginClass(app, manifest)
           ├─ await plugin._activate()  → onload()
           └─ 注入 styles.css(若存在)

用户在 Settings 启用 / 禁用插件:
  ├─ enable:同上 _activate()
  └─ disable:plugin._deactivate() → 所有 disposable LIFO 清理 + 移除 <style>

热更新(开发期):
  └─ 监听 ${userData}/plugins/<id>/main.js mtime → _deactivate → import?cacheBuster → _activate
```

## 信任模型

**v1:类似 Obsidian 的 Restricted Mode**

- 默认禁用所有插件,首次见到一个新插件目录提示用户"是否启用"
- 启用后该插件拿全权限(同进程,同 LM 内核)
- Settings UI 一个全局开关 "禁用所有第三方插件"
- 内置插件(`packages/core-plugins/*`)不走该机制,直接加载

**v2 可加(若有需要)**:Manifest declarative permissions(`fs-read / fs-write / network / shell`),首次启用提示授权。但这是后话,**v1 不投资**。

## 把现有内核重构为内置插件(吃自家狗粮)

LM 现在的 Editor / Terminal / Explorer / Output 都是硬编码到 DockShell 的。**M-Plugin v1 的最佳验证就是把它们重写成内置插件**:

```ts
// packages/core-plugins/editor/src/plugin.ts
export default class EditorPlugin extends Plugin {
  onload() {
    this.registerPanel({
      type: 'editor',
      factory: (props) => <EditorPanel {...props} />,
      title: 'Editor',
    });
    this.addCommand({
      id: 'editor.save',
      name: '保存当前文件',
      hotkey: 'mod+s',
      fn: () => this.app.events.emit('editor.save-request'),
    });
    // ...
  }
}
```

好处:
1. **API 设计正确性** — 自己用得舒服,第三方插件大概率也舒服
2. **回归覆盖** — 现有 BDD 测试都还在,改完通过 = API 表面没破
3. **可拔插性** — 用户不喜欢内置 Editor 可换其他实现

## 风险与决策记录(初版)

### ADR-Plugin-1:不做沙箱
- 选项 A:Web Worker 隔离(Lokus 走法)
- 选项 B:WASM 隔离(Zed 走法)
- 选项 **C:不隔离(Obsidian 走法)** ← 选这个
- 理由:LM 单用户 + AI agent 配套场景信任度高;React + Dockview + Zustand 都在主线程,隔离会引入异步 RPC,与"plugin 直接 import design 组件、订阅 store、加 Dockview panel"的核心价值矛盾;后期若需要可加 Manifest declarative permissions(M-Plugin v3),不阻断现在

### ADR-Plugin-2:ESM 不 CJS
- Obsidian 用 CJS 是历史(esbuild --format=cjs);LM 用 Vite,生态默认 ESM;插件代码里 `import.meta` 与 top-level await 都能用,体验现代化

### ADR-Plugin-3:核心暴露面用 LMApp 而非 window.api
- 原因:`window.api` 是 LM 内部 IPC 全集(fs / terminal / popout / layout 等),plugin 不该全拿;`LMApp.fs` 只挑文件读写子集,后续可加 capability;`LMApp.events` 是 LM 自定义事件总线,与 Dockview 自带事件解耦
- 副作用:Plugin SDK 包(`packages/plugin-sdk`)能跨项目复用 — 将来 Nous 也能拿同一份 Plugin 类来写工具集成

### ADR-Plugin-4:Plugin 目录用 userData 不用 vault
- Obsidian 是 vault-scoped(每个 vault 独立 plugin 集);LM 是 IDE,workspace 切换不应换插件集
- 决定:plugin 安装在 `{userData}/plugins/`,所有 workspace 共享;workspace 级配置走 `loadData/saveData`

## 与 Lokus 的对比(为什么不抄)

`/Users/RiGang/Desktop/LayoutMotion/examples/lokus` 是一个走 VSCode 模型的 markdown 编辑器,**值得反面参考**:

| Lokus | LM 决定 |
|---|---|
| `packages/plugin-sdk/src/types/manifest.ts` 的 `contributes` 大对象(commands / keybindings / menus / themes / views ...) | 不要 — 全部 imperative |
| `packages/plugin-sdk/src/types/permissions.ts` 50+ permission enum | 不要 — 单用户场景过度设计 |
| `src/plugins/security/PluginSandbox.js` Web Worker 沙箱 | 不要 — 与 React + Dockview 集成冲突 |
| `src/plugins/api/` 20 个 API class | 不要 — VSCode-fan-out,LM 8 个就够 |
| `packages/plugin-sdk/src/utils/base-plugin.ts` BasePlugin + DisposableStore | **抄!** — disposable 模型是这套 API 的脊柱 |
