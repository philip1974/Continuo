# 尚不存在的 scope 目录:授权落地的路径

行为契约:**插件请求的 fs scope 目录即使此刻还不存在,授权落地的路径也与之后 fs 操作校验用的路径
在同一空间** —— 目录之后被创建时这条授权照常生效,授权弹窗显示的也是一条正常的本平台路径。

## 背景

授权落地前 main 会把 scope 路径归一化(`~` 展开 + `realpath`),校验侧对 fs 操作的目标同样走
`realpath`。目录不存在时 `realpath` 失败,此前直接回退到「只展开 `~`」的字符串,于是:

- **分隔符**:`~` 展开是 `<home>` + `/dir` 的拼接,插件也可能直接写 `C:/proj/out` —— Windows 上落地成
  `C:\Users\x/dir`,弹窗显示混合分隔符。
- **已存在的上级目录没有被解析**:上级含符号链接(macOS `/tmp` → `/private/tmp`、`/var` → `/private/var`)
  或 Windows 8.3 短名(`C:\Users\RUNNER~1`)时,落地的是未解析的写法。

两种情况下,目录之后被创建,校验侧得到的是解析后的路径,与落地的 scope 做 `scope + 分隔符` 前缀匹配
对不上 → 这条授权永远不生效(误拒,不是越权)。

## 行为

- 绝对路径:对**最近的已存在上级目录**做 `realpath`,其后尚不存在的各级按原样接在后面
  (`/tmp/new/out` → `/private/tmp/new/out`)。
- 尚不存在的部分只做拼接:不折叠 `..`(含 `..` 的 scope 与改动前一样匹配不上任何目标,不会变成别的目录)。
- Windows 上结果里的 `/` 全部换成 `\`;其它平台不动(`\` 在 POSIX 是合法文件名字符)。
- 相对路径、没有任何上级能解析的路径:保持原有回退(只展开 `~`、去尾分隔符),外加上面的分隔符规则。
- 目录已存在:行为不变(整条 `realpath`)。
- 端到端:对一个尚不存在的目录授权 → 之后创建 → 目录内的读取通过校验;上级是符号链接时同样成立。

## 不在本主题验证

- `~user` 形式无法展开时退化为原始路径(见 `49-polish-bugfixes/scope-grant-canonicalizes-path.spec.ts`)。
- 弹窗如何渲染 `displayPath`(见 `plugin-fs-scope-display-path`)。
