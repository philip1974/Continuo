# agent-auth-prompt-throttle(agent 授权弹窗被拒后有冷却,不能循环弹窗诱导误点)

## 背景

威胁模型:被提示注入的 AI agent 在 Continuo 终端里运行,可经 stdio / HTTP 调 MCP。需授权的工具(terminal.* /
debug.* / plugin.*)在用户未授权时弹出授权弹窗。此前被拒后**没有任何冷却**(只有未决数上限 64/窗、256 全局):
agent 循环调用任一需授权工具、每次被拒立即再调,弹窗关一个来一个(实测顺序 500 次请求全部弹出),而弹窗会抢走
键盘焦点 —— 用户正在终端 / 编辑器打字时,Tab+Enter 落到「仅本次」,Tab Tab Enter 落到「本次启动期间允许」
(整域放行)。跨窗变体:别的窗口里的 agent 直连 socket 不发 hello,以 external 身份在主窗连弹并占住主窗唯一的
授权槽,主窗内合法 agent 的首次授权被自动拒绝。

同族:plugin-fs 的 scope 请求已有同样的节流(`plugin-fs-scope-request-throttle`),机制抽成
`electron/main/lib/prompt-throttle.ts` 两处共用。

## 行为

### 主进程(`agent-auth.service.ts` 的 `requestAgentAuth`)

节流按**调用方**(目标窗口 × 调用方类别:窗口内 agent / external 客户端)计,冷却按**授权域**(terminal / debug /
plugin)计;唯一的例外是**超时冷却按窗口**计(见「超时」)。

- **拒绝冷却**:用户拒绝后,该调用方的这个域进入冷却:30s 起,同一域每次冷却结束后再被拒翻倍,上限 5 分钟;距上次
  拒绝超过 10 分钟后退避级别归零。冷却期内该域的任何 method 都直接失败:不发 IPC、不弹窗。别的域不受影响(但见下一条)。
- **调用方级连续被拒退避**:同一调用方连续 3 次被拒(不论域,挡轮换 terminal → debug → plugin)→ 该调用方的所有域
  进入退避,30s 起每多被拒一次翻倍,上限 5 分钟。用户授予一次只把计数减 1。
- **超时**:弹窗 2 分钟(`AGENT_AUTH_PROMPT_TIMEOUT_MS`,此前 5 分钟)无人应答 —— 用户不理会 ≠ 拒绝,不升拒绝退避、不计连续被拒;但该**窗口**(窗口内 agent
  与 external 两类调用方)的所有域进入冷却:30s 起,连续超时(按窗口合并计数)翻倍,上限 5 分钟;用户对该窗口
  任一调用方的弹窗作出决定(允许 / 拒绝 / 仅本次)后连续超时计数归零。
  - 不按域记:按域记时轮换 terminal → debug → plugin、只发起不应答,弹窗一个超时下一个立刻顶上(审计实测 9 次
    请求弹 9 次共 2700s,占屏 ≈100%)。
  - 不按调用方记:按调用方记时同时用窗口内与 external 两个身份交替只发起不应答,一个冷却时另一个顶上(审计实测
    一小时 12 个弹窗、占屏 100%)。
  - 现在单身份轮换域、两身份交替都是一小时内 11 个弹窗、占屏 36.7%,稳态 120s / (120s + 300s) ≈ 28.6%(上限由超时
    时长与冷却上限决定;超时 5 分钟时为 8 个、62.5%,稳态 50%)。
  - 代价(产品决定):external 客户端的超时也让同窗口的合法 agent 冷却。拒绝冷却、退避、速率、单飞仍按调用方。
- **无应答超时从开始显示起算**:renderer 同一时刻只显示一个弹窗,另一类调用方的请求排在后面。main 在请求**成为显示中的
  弹窗**时开始计 2 分钟(据「该窗口最早的未决请求即显示中的那个」判断,不需要 renderer 上报);到点结算后向目标窗口发
  `agent-auth:cancelled`(带 requestId),renderer 据此关弹窗 —— renderer 不自行计时,过期只有 main 一个来源
  (退出清理 / 撤销的批量结算不逐个通知:窗口已隐藏 / 另有 REVOKED 广播)。此前各自从到达起计(审计实测):external 只发起不应答、冷却一结束就抢先
  占住显示,窗口内合法 agent 的请求排在其后、与它同时到期 —— 一小时内合法请求 11 次全部显示 0 秒即按超时拒绝;
  现在每次都轮到显示、由用户决定(同一模型下 24 次全部被「仅本次」放行)。排队请求显示到超时照常让窗口冷却。
  - **排队兜底上限 10 分钟**(`AGENT_AUTH_QUEUE_MAX_MS`,后备防线):排队这么久仍没轮到显示 → main 按**取消**结算
    (不计拒绝、不进冷却)。已授权域的请求在 main 直接放行、不入队,未授权请求每个调用方类别至多一个未决,正常情况下
    排队不超过前一个弹窗的显示时长(≤ 2 分钟)。
  - 纵深(保留):显示不足 5s 就到期的弹窗不记超时冷却。
- **速率上限**:同一调用方 60s 内最多 10 个弹窗(即使每次都被「仅本次」放行)。
- **单飞**:同一调用方同时最多一个未决弹窗。未决期间该调用方的新请求(不论域)直接失败,不排队、不计拒绝。
- **不计为拒绝**:窗口关闭、撤销、应用退出、IPC 发送失败结算的请求。
- 被节流的请求 reject `AGENT_NOT_AUTHORIZED`,消息说明原因与等待时长(工具门控原样返回给 agent),例如
  `the user denied (or did not answer) a recent authorization prompt; Continuo will not ask again for 30s`。
  agent 授权没有用户手动重试入口:用户想放行就让 agent 冷却后再试。
- **「本次启动期间允许」后不节流**:授权的权威在主进程(按 窗口 × 调用方类别 × 域 记)。用户对某域选了
  「本次启动期间允许」后,该域的请求在主进程直接放行 —— 不发 IPC、不弹窗、不入未决、不单飞、不计速率。撤销、
  窗口关闭、renderer reload 时清除(见下)。renderer 只持有界面副本(状态栏撤销入口)。
- **renderer reload / 渲染进程崩溃**(主窗 View 菜单 Cmd+R;窗口不关、webContents 不销毁,但 renderer 的授权态与
  弹窗随旧文档消失):main 在该窗口主框架的非同文档导航**提交**时(`did-navigate`;主框架加载失败 `did-fail-load`
  提交的是错误页,同样算;`ERR_ABORTED`(-3)不算 —— 真机上它出现在加载中又 reload(随后有 did-navigate)
  与就绪后主进程 `wc.stop()`(文档原样留着)两种情况)与 `render-process-gone` 时,把该窗口全部未决请求按**取消**结算(不计拒绝、不进冷却)并
  清掉它的授权(与 renderer 界面副本随旧文档清空一致)。
  此前(审计实测):①授权残留 → 该域请求不走节流:40 次请求每次点「仅本次」弹 40 次(上限
  应为 10)、连续超时无冷却、被拒后立刻再请求又弹;②弹窗显示中 reload → 弹窗消失而 main 的未决请求留到无应答
  超时,调用方一直「已有未决弹窗」,再加 30s 超时冷却 → 同窗口所有 agent 330s 拿不到弹窗(当时超时 5 分钟)。
- **reload 窗口期(新文档尚未订阅授权请求)到达的请求直接拒绝**。上一条把未决请求按取消结算后,agent 立即重试的
  那次 IPC 落在加载中的文档上(实测):没有可见弹窗,main 的未决请求占着槽等满无应答超时再进超时冷却,该窗口同类调用方
  **所有域**被拒约 330s(当时超时 5 分钟)。
  - 就绪握手:renderer 订阅授权请求(preload `agentAuth.onRequest` 挂上监听)后上报 `agent-auth:ready`(同
    `plugins:protocol-ready`);main 校验受信 frame,按发送方所在窗口记为就绪。`did-finish-load` 不算(React 挂载、
    订阅建立在其后)。
  - main 在窗口创建时(`browser-window-created`,首次加载之前)开始跟踪;主框架非同文档导航提交 / `render-process-gone`
    起到下一次上报就绪为止,以及主框架仍在加载(`isLoadingMainFrame`:导航开始到提交之间靠它)时,`requestAgentAuth` **立即** reject
    `AGENT_NOT_AUTHORIZED`(消息说明窗口正在重新加载、稍后重试):不发 IPC、不登记未决、不计拒绝、不进冷却。
  - 这些被拒的请求**计入速率上限**(窗口期狂刷重试 → 就绪后按超速拒绝,不连弹)。
  - 渲染进程崩溃后一直不恢复 → 该窗口的请求一直立即被拒(本来也显示不了弹窗),不再各自干等无应答超时。
  - **未提交的导航不算换文档**。Electron 先发 `did-start-navigation` 再发 `will-navigate`:被导航守卫拦下、被中止的
    导航只有「开始」没有「提交」,旧文档原样留着,不会再上报就绪。此前按「开始」置未就绪(实测:这样一次导航之后
    1 小时内每分钟一次请求 60/60 被拒,直到下一次 reload),显示中的弹窗也在 main 侧被提前取消。现在这类导航之后
    请求照常弹窗、显示中的弹窗照常可应答、「本次启动期间允许」不清。(`lib/wc-gone-hook` 的其它使用方 ——
    plugin-fs / plugin-mcp / 子进程回收 —— 仍按导航开始,语义不变。)
- **external 与窗口内互不占用**:两类调用方各自计拒绝冷却 / 退避 / 速率、各占一个未决槽(超时冷却除外,按窗口);
  不同窗口之间互不影响。

### renderer

- **按调用方类别分槽**(`agent-auth.store.ts`):窗口内 agent 与 external 客户端各一个槽。同一时刻仍只显示一个
  弹窗(不堆叠);另一类调用方的请求排在后面,当前弹窗落定后显示。同一类已占槽 → 立即 `denied`。renderer 不计时:
  main 从请求开始显示起按 2 分钟结算超时 / 排队兜底后经 `agent-auth:cancelled` 撤掉对应弹窗;main 撤销时显示中与排队中的一并 `cancelled`。
- **授予方向的防误触延迟**(`AgentAuthPrompt.tsx`;实现在 `src/lib/use-prompt-grant-guard.ts`,与插件权限弹窗共用,
  见 `permission-prompt/`):弹窗显示后 500ms 内,「仅本次」「本次启动期间允许」的鼠标 /
  键盘激活无效(弹窗保持);「拒绝」与 Esc 立即可用;初始焦点仍在「拒绝」。排队的下一个请求显示时重新计时
  (对旧弹窗的连点不落到新请求上)。
  - 延迟内被拒掉的授予激活把计时起点推到它自己的时刻(之后要再等满 500ms),且指针点击只认**单击**(`detail === 1`):
    实测出现后 +350ms 第一击无效、+560ms 第二击(双击的第二击,`detail=2`)落成「本次启动期间允许」。双击 / 多击的
    后几击任何时候都不算授予。
- **授予按钮的键盘激活须是停顿后的有意按键**(同一守卫)。出现延迟挡不住「晚到」的按键:用户没注意到弹窗,继续
  原来的输入流 —— Shift+Tab(Claude Code CLI 切模式)后打一句话再回车、Tab 补全后回车 —— 其中的 Space / Enter
  不能落成授予。
  - 「仅本次」「本次启动期间允许」的键盘激活(Enter / Space)要求:该按钮已持续聚焦 ≥ 500ms;聚焦期间没有打过字
    (打过字 → 须把焦点移开再回来);这一下按键不是键重复,且之前 500ms 内没有别的按键。不满足 → 无效,弹窗保持。
  - **输入流里的 Tab 带来的焦点不能用键盘授予**。上一条挡不住「Tab 之后停下来看一眼再回车」(实测:`c h e <Tab>`
    停 700ms `<Enter>` → 仅本次;弹窗刚出现时 `<Tab><Tab>` 停 600ms `<Enter>` → 本次启动期间允许 —— zsh 里补全 /
    双 Tab 看候选再回车)。把焦点带到授予按钮的那一下 Tab 若紧跟在别的按键后(< 500ms,或是键重复)、或在弹窗出现后
    500ms 内按下、或弹窗出现后打过任何字符,这次聚焦期间 Enter / Space 一律无效(等多久都一样);把焦点移开、
    停顿后再 Tab 回来,或用鼠标,才可用。
  - 键盘用户的操作方式:弹窗出现后停顿半秒,Tab 到要用的授予按钮(连按多下时每下之间也要停顿),再停顿半秒,
    按 Enter / Space。弹窗出现后若已经打过字,键盘只能拒绝(Enter 在「拒绝」上 / Esc),授予须用鼠标或等 agent 重新请求。
  - Shift+Tab 不能从「拒绝」回绕到末尾的「本次启动期间允许」(焦点留在「拒绝」;向前 Tab 仍可到达所有按钮)。
  - 鼠标点击只受出现延迟约束;「拒绝」的键盘激活与 Esc 不受任何限制。
- **被拒掉的指针点击不留下可用键盘授予的焦点**(同一守卫;`prompt-early-click-focus.spec.tsx`)。Chromium 在
  mousedown 时把焦点移到被按的按钮上:实测弹窗出现 +200ms 单击「本次启动期间允许」被拒,但焦点已在该按钮上,再过
  700ms 的 Enter 满足全部键盘条件 → 整域授予;双击落在「仅本次」、manifest 的「授权选中」、shell 勾选框 + Space 同理。
  - 指针点击会被拒的时刻(出现后的时间窗内 —— 含被拒点击推后的窗口;多击的后几击 `detail ≥ 2`),弹窗里的
    `mousedown` / `pointerdown`(鼠标、触摸、笔)被 `preventDefault`:焦点不随按下移入,click 照常派发并被拒、给提示。
    时间窗过后的单击不受影响(焦点照常移入、照常授予)。
  - 授予方向的指针点击被拒时,焦点若已在该控件上(按下时没拦住,或更早经别的途径聚焦):这次聚焦标为不可键盘授予
    (同「输入流里的 Tab」,焦点移开再回来才重置),并把焦点移回弹窗的初始焦点「拒绝」(不 blur:焦点落到 body 读屏会
    丢失位置;被拒原因由 status 区域播报)。之后的 Enter / Space 落在「拒绝」上。
  - 被拒的**键盘**激活不移动焦点(Tab 后立刻 Enter 被拒、停顿后再 Enter 授予,行为不变)。
- **被守卫拒掉的授予激活有可感知反馈**(`src/lib/prompt-grant-hint.tsx`,三种授权弹窗共用):此前被拒只是「没反应」
  —— 过早的点击、Tab 后立刻回车,以及辅助技术合成的点击(`detail=0`、没有 keydown、DOM 焦点可能不在按钮上,可能
  一直无效)。弹窗按钮行**上方**常驻一个 `role="status"` 区域(空;占一行高度,提示出现时弹窗不跳动;放在按钮上方占用正文与按钮之间的间距,底部不多出空白);授予方向的激活被拒
  时写入提示(`permissions.grant_guard.rejected`:稍作停顿后再单击,或聚焦片刻后再按 Enter / 空格),可见且会被读屏
  播报;4s 后、有效的授予方向操作后、请求切换后清空。**规则不放宽**:焦点不在按钮上的合成点击仍然无效。

## 规范

- `main-throttle.spec.ts`:真实 `agent-auth.service` + 真实节流(fake timers):审计复现(500 次只弹 1 次)、
  冷却到期与退避增长、按域记、轮换域退避、授予 / 超时 / 取消不计拒绝、速率上限、单飞、session 授权后不节流、
  撤销与 reload 后恢复节流、external 与窗口内 / 不同窗口互不占用。
- `renderer-reload.spec.ts`:真实 `agent-auth.service` + 真实 renderer store(fake timers):「本次启动期间允许」后
  reload(main 收到导航事件)→ 40 次「仅本次」≤ 10 个弹窗、超时有冷却、拒绝有冷却;弹窗显示中
  reload / 渲染进程崩溃 → 未决请求立即结算、新请求马上可弹、不计拒绝;同文档导航不结算。
  未提交的主框架导航(只有 did-start-navigation)→ 请求照常弹窗、显示中的弹窗与授权镜像保留;开始到提交之间靠
  `isLoadingMainFrame` 拒;主框架 did-fail-load → 未就绪(ERR_ABORTED -3 除外:加载中又 reload、就绪后 `wc.stop()`
  两种真机序列都最终就绪)。
  reload 窗口期(未上报就绪 / 主框架加载中)的请求立刻被拒、不发 IPC、不锁死、计入速率;就绪后正常弹窗。
- `prompt-grant-feedback.spec.tsx`:status 区域常驻、被拒时出现提示并定时清空、合成点击仍无效但有提示、请求切换清空。
- `renderer-ready-handshake.spec.ts`:preload 先挂监听再上报 `agent-auth:ready`;main 的 READY 处理器与窗口创建时的跟踪接线。
- `timeout-occupancy.spec.ts`:真实 service + 真实 renderer store:超时时长 120s(main 结算、renderer 同时关弹窗);三域轮换只发起不应答的占屏比例、超时冷却不按
  域记、连续超时翻倍与封顶、用户决定后归零、超时不算拒绝;窗口内与 external 两身份交替只发起不应答的占屏比例、
  超时冷却与连续超时计数按窗口合并、任一调用方上的决定归零、拒绝冷却仍按调用方;排队请求从开始显示起
  计 120s(审计复现:external 抢占显示时合法 agent 的请求每次都轮到显示并被用户放行;main 结算 = renderer 关弹窗;
  显示到超时照常进冷却)、排队 10 分钟兜底按取消结算不进冷却。
- `store-slots.spec.ts`:renderer 分槽与排队。
- `prompt-grant-guard.spec.tsx`:500ms 内「允许」无效、「拒绝」/ Esc 有效、初始焦点、排队切换后重新计时。
  双击第二击跨过延迟不授予、过早的点击重新计时、`detail ≥ 2` 不算授予。
- `prompt-early-click-focus.spec.tsx`:过早的单击 / 双击被拒后停顿再按 Enter 不授予(焦点回到「拒绝」);时间窗内与多击
  的按下被 preventDefault、时间窗过后与弹窗外的不被;被拒后等满时间窗再点 / 再 Tab 过去按 Enter 仍可授予。
