# plugin-fs-scope-request-throttle(scope 授权请求被拒后有冷却,不能循环弹窗诱导误点)

## 背景

`plugin-fs:request-scope` 被用户拒绝后没有任何冷却:有 `fs` 权限的插件可以在拒绝回调里立刻再次
`requestScope`,弹窗关掉一个又来一个,直到用户误点「允许」。`canAccept` 只限制**同时**未决的请求数。

## 行为

- **拒绝冷却(按单条路径)**:用户对某次请求点了拒绝后,请求里的**每条路径**(归一化后;不看 mode、不看和哪些
  路径一起请求)各自进入冷却。冷却期内,同一插件的请求只要包含其中任一路径、或包含它的**祖先目录**(把被拒目录
  包进更大的范围再问),整个请求直接返回 `deny`,不向 renderer 发弹窗。所以被拒后换成 `[被拒路径, 新目录]`、
  `r` 换 `rw`、换父目录都不会再弹。冷却期 30s 起,同一路径每次冷却结束后再被拒翻倍,上限 5 分钟;距上次拒绝
  超过 10 分钟后退避级别归零。
- 「同一路径 / 祖先目录」按**文件身份**判,不只看路径字符串:同一目录的另一种写法(realpath 不归一的别名 ——
  macOS 数据卷 `/System/Volumes/Data/<绝对路径>`、Linux bind mount、Windows subst)同样命中冷却。已存在的各级按
  (dev, ino);尚不存在的路径按「最近已存在上级的身份 + 余下各段名字」(macOS / Windows 上忽略大小写与 Unicode
  规范化形式)。取不到身份(stat 失败)时退回只按路径字符串。
- 被拒路径的**子目录**是缩小范围,可以弹;它被拒后同样进入冷却并计入插件级退避。
- 冷却结束后可以再弹;用户这次允许 → 正常授予,并清除这些路径的拒绝记录。
- 冷却按插件、按路径分别计:别的插件、同一插件请求不相干的目录不受影响(但见下一条)。
- **插件级连续被拒退避**:同一插件连续 3 次被拒(不论请求的是什么)→ 该插件的所有 scope 请求在退避期内直接
  `deny`。退避 30s 起,之后每多被拒一次翻倍,上限 5 分钟;退避结束后(未进入退避则为上次被拒后)超过 10 分钟
  没有再被拒 → 计数清零。退避期本身不算「没有被拒」。
- 用户授予一次 → 连续被拒计数只**减 1**(不清零),已生效的退避不提前解除。所以「拒、拒、(请求一个无害小目录
  骗到)允、拒、拒、允…」照样会进入退避。被授予的只清除**这些路径自己**的拒绝记录,别的被拒路径的冷却不受影响。
- **弹窗速率上限**:同一插件每 60s 最多发出 10 个授权弹窗(不论请求的是什么),超出直接 `deny`。
- **每插件单飞**:同一插件同时最多一个未决的授权弹窗(跨窗口合计)。弹窗未决期间该插件再 `requestScope`
  (不论请求什么)直接返回 `deny`:不排队、不弹窗、不计入拒绝冷却。所以插件不等结果同步连发 10 次同一请求只会
  弹 1 个,用户拒绝后没有排着队的下一个;冷却到期后再连发也是每个周期最多 1 个。
- 弹窗以任何方式收口后,该插件即可再次请求:用户允许 / 拒绝、超时(请求 reject)、窗口关闭或 renderer reload、
  弹窗发送失败、插件实例被注销(卸载 / 禁用 / reload)。
- 插件实例被注销时,它的未决请求在主进程按 `deny` 收口(不是用户的拒绝,不计入冷却;迟到的决定不落地)。
- 请求在主进程收口而 renderer 还在(超时 / 插件注销)→ 主进程通知 renderer 撤掉对应弹窗并显示队列里的下一个,
  renderer 不再回传决定(见 `plugin-fs-scope-bridge/scope-request-cancelled.spec.ts`)。
- 已被现有授权覆盖的请求照旧静默 `grant`,不计入速率、不受冷却影响。
- 记录只在主进程内存里(重启应用即清空),数量有上限。
- **开销有界**(`scope-request-fanout-bounds.spec.ts`)。路径是插件给的,可以「很短的段 × 很多级」(8190 字符
  ≈ 4080 级);冷却键要逐级 stat 取文件身份。此前全量并发、缺失的各级逐级拼接余下各段(键长是层级数的平方),
  且在任何节流判定之前 —— 实测一次请求 64 条这样的路径,主进程事件循环卡死 10s、RSS +2.8GB,5 次并发堆耗尽。
  - 入口:scope 路径最多 64 级(`MAX_SCOPE_PATH_DEPTH`,`validateScopesShape`,renderer 发 IPC 前与主进程同一
    校验),超出 → `BAD_INPUT`,不归一化、不算键、不弹窗。
  - 算键:层级数超过 128(canonical 化后可能比请求写法深)的路径不 stat,只按路径字符串记;各路径共有的上级只
    stat 一次;同时在途的 stat 最多 16 个;缺失的各级各记一个定长的链式摘要(键长与层级数成线性);单个键有字符数
    上限,超出退回纯路径键。每插件记住的被拒键数上限不变(64)。
  - 顺序:未决数到顶、该插件已有未决弹窗 / 在退避期 / 弹窗超速的请求先被拒,不算键(不触发 stat)。
  - plugin-fs 各操作(readFile / writeFile / listDir / stat / lstat / realpath / mkdir / rename / rm / cp /
    atomicReplace / readGitBlob)的 target 最多 256 级(`FS_PATH_MAX_DEPTH`),超出与超长一样按
    `invalid target path` 拒绝,不进 scope 校验里按层级逐级处理的部分。

## 残余

- 层级数超过 128 的 canonical 路径只按字符串记冷却,不带文件身份(别名换写法可避开**单路径**冷却;插件级连续
  被拒退避与速率上限仍然生效)。真实目录到不了这个深度。
- 处于单路径冷却(而非插件级退避 / 超速 / 单飞)的重复请求仍要先算键才能判定(每次 ≤ 64 条 × 129 级的 stat,
  有界并发);这与每次请求都要做的路径归一化同一量级。

- 插件可轮换请求不同的目录,在连续被拒 3 次进入退避之前继续弹窗(之后每个退避期最多 1 个)。
