# editor-milkdown-roundtrip-verbatim

行为契约:**Markdown 编辑模式(Milkdown)改一处保存,只有被改的那一块变化** —— 其余块逐字节原样,块间空行与文末空行照旧,
CRLF 文件仍是 CRLF。

## 背景(第四十八轮审计 A2–A4)

- CRLF 的 `.md`(含 UTF-16 LE CRLF)在编辑模式改一字 ⌘S → 整篇变 LF,状态栏也变 LF(编码保住、行尾没保住)。
- 只按「全文风格推断」(`editor-milkdown-roundtrip-style/`)时,改任意一处,别处的常见写法仍被 remark-stringify 改写:
  `|---|---|`、`| --- | --- |` → `| - | - |`;`|:----:|------:|` → `| :-: | -: |`;无首尾竖线的表格被补竖线、紧凑表格被补空格;
  裸链接 `https://b.com.` → `<https://b.com>.`;行尾两空格硬换行 → `\`;`1. 1. 1.` → `1. 2. 3.`;文中 `[x]` → `\[x]`;
  文末多余空行被删。

## 行为

- 未改动的顶层块原样写回:挂载时(随 Milkdown 对初始内容的那次解析,不另解析)记下每个顶层块的 ProseMirror 节点、源码区间与
  块间原文。序列化时逐块找原文块 —— 同一节点(拖动重排、撤销都还原同一节点),或内容相同(忽略标题 id、有序列表项 label
  这类不写进 Markdown 的属性;删一字再输回同一字也算)。在原文里也相邻的两块之间写原文的块间空白,文首文末同理。
- 被改动的块:夹在两个原文块之间且与原文一一对应(只改了块内容)时,块间空白照旧,并按该块自己的原文写法写(列表符号、编号是否
  递增、setext / ATX、围栏……);**列表逐项**、**表格逐行**再找原文:未改的项 / 行原样;改动的列表项按原列表的符号与编号单独写;
  改动的表格行按原表格的首尾竖线 / 空格写,分隔行在列数与对齐未变时原样;Prettier 对齐的表格(各行等宽且分隔行同样带空格)
  列宽不变时只变那一行、列宽变了整表按 Prettier 重新对齐。拼好的列表 / 表格用同一解析器试解析,结构与当前块不同就退回 remark。
- 被改动块内部的写法按原文件推断(见 `editor-milkdown-roundtrip-style/`):裸链接(前后是空白 / 换行 / 段首段尾,后面可有句末
  标点,地址形状保守)、行尾两空格硬换行、`1. 1. 1.`、文中 `[x]`(不在段首、后面不是 `(` / `[` / `:`)。
- 被改动的块只改了一处文字(打字 / 删字,标记与结构不变)时**就地改原文**:在原文里替换那几个字(文字、行内代码里,或两个
  行内节点之间),块里其余字节不变;替换后用同一解析器解析回来须与编辑后的块相同,否则按上面的写法重写(第五十轮:`$b `$`
  按 Pandoc 规则是公式、吞掉一个反引号,其后的反引号错配成跨行(含硬换行那一行)的行内代码 —— 整块重写时 remark 把行内代码里
  「换行 + 可能被当成块开头的字符」换成空格、去掉两端补的空格,改一字看起来像硬换行丢了、反引号错位,解析回来也变了)。
  表格不就地改(对齐的表格改了列宽要整表重排)。
- 硬换行写法按行尾两空格、而前面的文字以空白结尾(原文 `a \` 写法)时写 `\`:行尾空白整个算进硬换行,写两空格会吞掉那个空白
  (紧跟裸链接、换行并入链接时同样)。
- 安全网:被改动的块按原文写法(块风格推断、裸链接、`$` 不转义、列表逐项 / 表格逐行)写出后同样试解析,与编辑后的块不同 →
  依次退回:同写法但保留行内代码里的换行、全文风格的 remark 默认写法、保守写法(地址同文的链接写 `<url>`,文字里的 `$` 与反引号
  一律转义;再加保留换行),取第一个解析回来相同的;都不同则仍用原文写法。
- 拆分 / 合并 / 插入新块:那一段走 remark(全文风格),与相邻原文块之间写一个空行;其余块原样。
- 两个列表(或列表与代码块)因删除 / 移动变成相邻而原文不相邻:不原样拼接(否则合并成一个列表),并入 remark 那一段由它换用
  列表符号;原文最后一块是没闭合的围栏代码块、后面又接了块:该块不原样写(否则吞掉后面的内容)。
  没闭合的围栏延伸到文末、区间吞掉了文末换行:它没有原样写在末尾(后面接了块 / 被改动 / 被删)时,原文以换行结尾则输出也以换行
  (CRLF 文档为 CRLF)结尾,原文没有文末换行的仍没有(第四十九轮 A2)。
- 行尾:原文件所有换行都是 CRLF(与 CodeEditor、状态栏同口径)→ 输出统一成 CRLF(原样块、remark 写的块都是);LF / 混合行尾的
  文件不改行尾。状态栏「更改行尾序列」(内容同步进编辑器)后按新内容重建原文块与行尾,之后的保存按新行尾写。
- 源码 ↔ 编辑切换按模式重挂载,按挂载时的内容重建;另一编辑器组改了内容(同步进本视图)同样重建。
- 性能:未改的块不走 remark,1 万行文档改一处的序列化从约 200ms 降到几毫秒(jsdom 实测)。

### 退回风格推断的结构

- 列表项里的子列表 / 引用里的块不再逐层原样:所在顶层列表项(或整个引用)被改动时按风格推断重写(同一列表里未改的项仍原样)。
- 有序任务项(`1. [x] a`):Milkdown 序列化本就丢勾选框,被改动的项随之丢失(未改的项原样保留)。
